The Evidence Pack module transforms K1's vulnerability findings from raw data
into professional, reproducible proof-of-concept packages ready for manual
review by security experts (HiL validators).

CORE OBJECTIVE: Every finding submitted for HiL validation includes:
  ✓ Automated screen recording of exploitation sequence (MP4/WebM)
  ✓ Standalone reproducible scripts (curl, Python requests, full exploit)
  ✓ Comprehensive evidence bundle with markdown report, video, scripts, logs
  ✓ PGP-signed approval workflow blocking platform submission
  ✓ Immutable audit trail of approvals and rejections

KEY ARCHITECTURE DECISIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. GLOBAL SINGLETONS FOR CROSS-MODULE ACCESS
   Why: Each module (recording, script generation, bundling) may be called
        from different agents at different times. Global instances (via
        get_recording_engine(), get_repro_generator(), get_hil_bundle_generator())
        allow any module to interact without deep reference passing.

2. ASYNC/AWAIT THROUGHOUT
   Why: K1's architecture is fully async. All evidence pack operations
        (recording, bundling, approval waiting) use async to integrate
        seamlessly without blocking the mission orchestrator.

3. IMMUTABLE AUDIT TRAILS
   Why: Approval decisions are security-critical. Every approval, rejection,
        and signature submission is logged to approval_log with timestamp
        and approver identity for forensic analysis.

4. SENSITIVE DATA REDACTION
   Why: Generated scripts must be shareable without exposing API keys or
        session tokens. Automatic redaction of Authorization, x-api-key,
        and cookie headers protects sensitive credentials.

5. STRUCTURED EVIDENCE PACKAGING
   Why: ZIP files with organized subdirectories (scripts/, evidence/, logs/)
        make evidence easier to navigate for human reviewers. BUNDLE_MANIFEST.json
        provides machine-readable metadata for tracking and auditing.

6. PGP SIGNATURE VALIDITY WINDOW
   Why: A signature that never expires could be replayed in the future.
        Configurable validity_hours (default 24) ensures approvals are
        time-bound and require fresh re-approval if bundles are reused.

7. GRACEFUL HANDLING OF MISSING EVIDENCE
   Why: Video recording might fail, or logs might not be available in
        sandboxed environments. Bundles validate file existence and log
        warnings for missing optional evidence rather than failing entirely.

Approval Workflow:
  1. Bundle created → status: PENDING
  2. HiL reviewer examines evidence
  3. Reviewer signs: k1 approve abc123 --pgp-sign <signature>
  4. PGPSignature submitted → status: APPROVED
  5. can_submit_to_platform(abc123) returns True
