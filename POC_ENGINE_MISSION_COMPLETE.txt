━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. PLAYWRIGHT FOR HEADLESS RECORDING
   Why: Browser-agnostic (Chromium, Firefox, WebKit)
        Records actual browser rendering (not just HTTP logs)
        Captures user interactions (clicks, inputs, waits)
        Cross-platform support (Linux, macOS, Windows)

2. SENSITIVE DATA REDACTION AT GENERATION
   Why: Scripts are shareable without exposing credentials
        Authorization, X-API-Key, Cookie headers marked <REDACTED>
        Safe to include in evidence bundles for external review
        Prevents credential leakage in HiL validator inbox

3. MULTIPLE SCRIPT FORMATS
   Why: Curl for quick validation (no Python required)
        Python requests for customizable reproduction
        Standalone exploit class for complex multi-step chains
        Bash for integration into existing workflows

4. PGP SIGNATURE VALIDATION
   Why: Cryptographic proof of approver identity
        Immutable audit trail (cannot be forged retroactively)
        Time-bound window prevents indefinite approval reuse
        Prevents unauthorized platform submissions

5. ZIP BUNDLE WITH ORGANIZED SUBDIRECTORIES
   Why: Easy navigation for human reviewers
        Machine-readable manifest for automation
        Separates concerns (evidence, scripts, logs, report)
        Reduces clutter in evidence directory

6. ASYNC/AWAIT THROUGHOUT
   Why: Non-blocking integration with K1's mission engine
        RecordingSession.start() doesn't block orchestrator
        script_generator.generate_*() functions non-blocking
        Multiple bundles can be processed in parallel

7. GLOBAL SINGLETONS WITH ASYNC INITIALIZATION
   Why: Any module can access recording/bundling without passing references
        Lazy initialization on first use
        Single source of truth for configuration
        Proper cleanup on shutdown
