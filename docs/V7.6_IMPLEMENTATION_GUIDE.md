# Kaison K1 Platform v7.6 - Implementation Guide

## Overview

Version 7.6 introduces major platform expansions focused on intelligence integration, AI model management, and enhanced visualization capabilities.

## New Features

**Backend:**
- `apps/backend/src/core/intelligence_engine.py` - Intelligence aggregation and analysis
- `apps/backend/src/integrations/rss_parser.py` - RSS feed parsing and monitoring
- `apps/backend/src/routers/intelligence.py` - Intelligence API endpoints

**Frontend:**
- `apps/frontend/src/components/intelligence/RSSIntelligenceDashboard.tsx` - Intelligence dashboard UI

**Key Capabilities:**
- Real-time RSS feed monitoring from multiple security sources
- CVE and vulnerability intelligence aggregation
- Relevance scoring and categorization
- Temporal trend analysis

**API Endpoints:**
```
GET  /api/v1/intelligence/feeds - List configured RSS feeds
GET  /api/v1/intelligence/items - Get intelligence items
GET  /api/v1/intelligence/stats - Get statistics
POST /api/v1/intelligence/scan - Trigger manual scan
POST /api/v1/intelligence/rag/query - Query RAG system
```

## Architecture

### Backend Stack
- FastAPI for REST/WebSocket APIs
- Ollama for local AI models
- LlamaIndex for RAG
- Neo4j for graph database (optional)
- RSS parsing for intelligence feeds
- Multiple email providers for notifications

### Frontend Stack
- React 18+ with TypeScript
- Vite build system
- Canvas API for graph rendering
- D3.js for advanced visualizations (recommended)
- Recharts for heatmaps (recommended)

## Startup Sequence

The application initializes services in this order (see `apps/backend/src/app/main.py`):

1. **KaiOrchestrator** - Core orchestration engine
2. **Watchdog** - Log monitoring service
3. **NotificationService** - Email/Slack/Webhook notifications
4. **LlamaIndex RAG** - Document indexing and retrieval
5. **Intelligence Engine** - Background RSS scanning (60 min intervals)
6. **Neo4j** - Graph database (optional, requires credentials)

All services have graceful fallback if not configured.

## Configuration

### Environment Variables

```bash
# Neo4j (optional)
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=your_password

# Gmail OAuth (optional)
GMAIL_CLIENT_ID=your_client_id
GMAIL_CLIENT_SECRET=your_client_secret

# Ollama (auto-detected)
OLLAMA_HOST=http://localhost:11434

# RSS Feeds (configured in code or DB)
INTELLIGENCE_SCAN_INTERVAL=60  # minutes
```

### File Locations

- **Authorized Scope:** `config/authorized_scope.json`
- **Permission Slips:** `vault/permission_slips/`
- **Logs:** `var/lib/kai/logs/`
- **Reports:** `var/lib/kai/reports/`

## Troubleshooting

### Ollama Not Running
```
Error: Ollama service is not available
Solution: Install and start Ollama from https://ollama.ai
```

### Neo4j Connection Failed
```
Error: Neo4j startup error (optional)
Solution: This is optional. Set NEO4J_PASSWORD env var or ignore.
```

### RSS Feeds Not Loading
```
Error: Intelligence Engine startup error
Solution: Check internet connectivity and RSS feed URLs
```

### RAG Not Working
```
Error: LlamaIndex RAG startup error
Solution: Ensure Ollama is running and models are installed
```

## Performance Considerations

### Backend
- Intelligence Engine scans every 60 minutes (configurable)
- RAG queries are cached for 15 minutes
- Ollama model downloads can be large (2-7GB)
- Neo4j queries are optimized with indexes

### Frontend
- Graph canvas rendering limited to 500 nodes for performance
- Intelligence dashboard auto-refreshes every 60 seconds
- Heatmaps re-render only on data changes

## Security

All v7.6 features maintain existing security guarantees:
- OAuth for Gmail authentication
- Webhook secret validation
- Permission slips for agent operations
- Audit logging for all actions
- No credentials stored in plaintext
